# 06 — UX architecture

## The bet

The primary flow is **six taps to a rendered Reel**:

```
Create From Reference → pick video → Close Match → add photos → Create Video → Export
```

Everything else in the app is an *escape hatch* from that line, not a step on it. The editor is
where you go to refine, not where you go to finish the job — but it is a full editor, because
the moment Auto Arrange is wrong you need trim handles, not a slider.

## Screen map

```
Home ──┬── Create From Reference ─▶ Reference Import ─▶ Analysis ─▶ The Style
       │                                                    (mode + reference audio)
       │                                                          │
       │                                     ┌────────────────────┘
       │                                     ▼
       │                            Your Content ─▶ Arrange ─▶ Editor ─▶ Export
       │                              (media, words, sound)   (pins)      │
       ├── From Scratch ──────────▶ Your Content ─────────────▶ Editor    │
       ├── Templates ─────────────▶ Library ─▶ Your Content ─▶ Arrange ─▶ Editor
       ├── Continue (grid) ────────────────────────────────────▶ Editor ◀─┘
       └── Settings ─▶ Diagnostics
```

**Home** has one hero card — *Create From Reference* — two tiles under it (*Templates*, *From
Scratch*), then *Continue*: a two-column grid of projects with rendered poster frames, duration
and scene count, favourites starred, sorted by recent / name / favourite, searchable past five
projects, and rename / duplicate / favourite / delete on long-press. A *Templates* strip closes
the screen. Drafts are not a separate destination: an unfinished project *is* a draft.

**Templates** lists saved styles (analysed from references, marked YOURS) and ten built-in
starters, filtered by category chips (Product, Fast Reel, Photo Montage, Cinematic, Minimal,
Travel, Text Heavy, …). Each card draws the style's actual scene rhythm over its palette, so a
fast reel and a slideshow look different at a glance. Tap previews; long-press renames,
duplicates, exports a `.reframestyle` file, or deletes. Import comes from Files or from any app's
share sheet — the app declares the document type.

## Analysis screen

Honest progress, which is harder than a fake percentage and much better:

```
Analysing your video

✓  Read video            15.4s · 1080×1920 · 30fps
✓  Found scenes          12 scenes
◐  Tracked motion        7 camera moves
◐  Read text             2 layers so far
✓  Listened to audio     128 BPM · 41 beats
○  Built style
```

Audio and text now run *alongside* the motion pass, so two rows tick at once. Stages complete
with a real result; determinate bars appear only where the denominator is genuinely known;
cancel is real and cooperative. A single continuous shot is reported as "1 continuous shot",
not as a failure.

## The style (summary)

```
REFERENCE UNDERSTOOD
Fast cuts

 15.4s      12       9:16
duration  scenes    format
 128        4        7
 BPM    text layers  camera moves
  6        No        30
transitions speech   fps
```

Then two decisions:

- **How closely to follow it** — *Close Match* (recommended), *Use Style* (pacing, transitions,
  motion, rhythm; your own text placed your way), *Use Structure* (only the cut skeleton).
- **Reference audio** — *Use my own audio* (default) or *Keep the reference's audio*, which
  extracts the soundtrack into the project on that tap and says, in the same breath, that you
  need the rights to it. *Save audio to Files* is there too.

Every inference under 80% carries a **Guessed** badge that explains itself in plain language.
Scenes expand to show start, entering transition, camera move and where the subject sat.

## Your content

Photos and clips (with a live *have / need* count and a shortfall hint), the words for each text
slot with "~17 chars fits" hints (Close Match only), and **Sound**: add music from Files, record
a voiceover (big red button, live meter, pause / retake), the extracted reference audio if you
kept it, and *keep sound from my clips*. Optional: match the reference's look, reorder, add a
logo. One button: *Auto Arrange* (or *Create Video* from scratch).

## Arrange

One row per scene: the reference described as *what it was* ("wide · push in · 1.2s") — never a
frame of it — an arrow, and your photo with the actual reason it was chosen. Tap to see every
photo ranked for that slot; picking one **pins** it. Pinned slots survive *Auto Arrange* and
*Shuffle*. *Create Video* binds, saves and opens the editor — the old "generating" screen that
animated six stages for a few milliseconds of work is gone.

## Editor

```
┌──────────────────────────────┐
│          preview             │  tap to play · drag text to place it
│    (canvas-fitted MTKView)   │
├──────────────────────────────┤
│ ruler                        │
│ [thumb][thumb][thumb][thumb] │  clips: tap selects, handles trim, long-press drags to reorder
│  ▭ text chip   ▭ text chip   │  text: drag to move, edges trim
│  ~~~ music waveform ~~~~~~~  │  audio lanes per role, with waveforms and fade ramps
│  ~ voice ~                   │
├──────────────────────────────┤
│ contextual tools for what's selected                                │
│  nothing:  Add media · Add text · Audio · Captions · Canvas · Look · Save style
│  clip:     Split · Replace · Transition · Framing · Speed · Adjust · Volume · Duplicate · Delete
│  text:     Edit · Style · Start here · End here · Duplicate · Delete
│  audio:    Levels · Mute · Start here · Split · Delete
├──────────────────────────────┤
│  Text        Audio        Look        Export                        │
└──────────────────────────────┘
```

Every panel is a bottom sheet with the same scaffold (title, Done, detents), built from the same
handful of controls (chips, choice cards, labelled sliders, swatch rows), so forty controls feel
like one product:

- **Text** — layer strip, then Style / Font / Animate / Timing tabs. Nine presets first (Clean,
  Headline, Caption pill, Outline, Highlight, Editorial, Tracked, Script, Type); then colour,
  size, opacity, shadow / outline / background / caps toggles, rotation; sixteen bundled faces
  with weight and italic, tracking, line spacing; entrance and exit animations; timing with
  "start / end at playhead" and "whole video".
- **Audio** — every track with its role, level, fade in / out, mute, "start at playhead", "fit
  to video"; add music, record voiceover, keep reference audio; per-clip sound; duck music under
  voice; the reference's tempo.
- **Look** (Style) — filter presets, apply-to-all, colour (brightness / contrast / saturation /
  warmth), effects (vignette / grain), framing (Fill / Fit / Smart crop, push in / pull out /
  static), clip volume.
- **Transition** — ten kinds in a grid, duration, direction, apply to all.
- **Speed** — presets 0.25× – 4× and a custom slider, with a footage-length warning.
- **Replace** — from the project pool or Photos.
- **Canvas** — 9:16 · 4:5 · 1:1 · 16:9 (crops re-solve around subjects), frame rate, background.
- **Captions** — pick the voice or reference track, pick a style, one tap; words appear as
  spoken. On device, language pack fetched by the system on first use.
- **Save style** — the current structure as a reusable template.

### Timeline

`UIScrollView` in a `UIViewRepresentable` — not SwiftUI. Playhead fixed at centre; the timeline
moves under it. Pinch 0.5–40 s across the width; snapping to clip boundaries, beats and the
playhead with a soft haptic, thresholds scaled to zoom. Clips draw their thumbnails tiled;
transitions mark the incoming edge; badges show motion, speed and clip audio. Trim handles are
16 pt bars with a grip that appear only on the selected clip; the scroll view yields to them.
Long-press picks a clip up; a drop indicator follows the finger. Every gesture is one undo step
because it opens and closes a coalescing gesture on the document.

### Undo/redo

Command pattern, not snapshots. `TimelineDocument.perform` is the only mutation path; commands
carry both new and previous values; continuous gestures coalesce by key. Every command is
Codable and the stack is persisted with the project, so undo survives a force-quit.

## Design system

Native-feeling, not branded-heavy.

- **Type**: SF Pro with `.rounded` for numerals and controls; Dynamic Type honoured throughout,
  including the timeline's labels.
- **Colour**: system semantic colours; one warm accent gradient, used only for the primary
  action and selection. Dark mode is the primary design; light mode fully supported; the user
  can pin either in Settings.
- **Depth**: three elevations — flat, raised, floating — and one hero surface per screen.
- **Motion**: `.snappy` for state, `.smooth` for content, nothing over 350 ms; reduce-motion
  degrades to cross-fades.
- **Haptics**: selection on snap, light impact on grab, success on export. Nothing else.
- **Touch targets**: 44 pt minimum via `.minimumHitTarget()`.
- **Empty states** propose the next action rather than describing the absence.
- **Errors** carry an action, not an apology: *Open Settings*, *Export at 720p*, *Add Photos*.
- **Accessibility**: every control labelled; timeline scenes and mapping rows are combined
  accessibility elements with spoken descriptions.
